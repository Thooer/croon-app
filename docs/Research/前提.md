# 前提的证据

这里保留 App 侧关于模型、上下文、认知模式和组织的研究线索。全部待核验：名称与数据来自网页端 LLM 的搜索报告，尚未对照原文，只作线索。

## 模型与上下文

研究线索包括：上下文中间位置的注意力较弱；模型可能被表面线索带偏；早先值会压制后来值；模型不会自动把自报把握转成停止或检验；同一模型的错误具有相关性；结构化程度的收益依赖模型与任务；更大的模型不必然更会发现工具使用时机。

推断：上下文管理、停止、独立检验、工具目录和异质模型应由 Library 与 Application 设计，不写成 Kernel 机制。

## 截断与续写

研究观察：模型经常不标记截断；从自我摘要恢复可能把故事当成状态；中断和多轮续写会降低任务质量。

推断：ReAct 遇截断以失败结束；恢复使用已记录的交付与 Journal，不能把模型自报状态当事实。中断只在 Atom 之间发生。

## 反馈与修正

研究观察：失败调用的表面形式会被模仿；追加反馈可能覆盖好结果；就地编辑和明确方向可能更有效；模型作为裁判会低估反馈，绝对评分不如相对比较稳定。

推断：失败怎样呈现、是否保留旧结果、怎样聚合和怎样比较是认知模式的策略。Library 保留选择空间，Application 按场景固定。
