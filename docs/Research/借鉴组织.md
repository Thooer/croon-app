# 借鉴组织

组织是人类长期实践中发展出的、协调多个行动者的结构。Croon 借鉴它，但不照搬。文中引用的研究全部待核验：名称与数据来自网页端 LLM 的搜索报告，尚未对照原文，只作线索。Kernel 侧的制度对照在 croon 的 docs/Research/借鉴组织.md。

## 迁移判据

用系统设计里的职责分离、接口与封装，项目管理里的目标分解、责任与授权，来检验模型。只借鉴能落到设计、减少概念混用的部分。一条组织规律能否迁移，看它依赖什么：

- 只依赖结构的，如授权、统一指挥、对外代表：直接迁移。
- 依赖动机或惩罚的，如激励、声誉压力、义务感：只迁移它的结构对应物。LLM 驱动的 Cognizer 没有偏好，惩罚无从生效，提示里的规则也不可靠；约束只能由结构给出，出了错追究的是归因与纠正，不是过失。
- 依赖成员错误独立的，如多数决、多人复核：先确认独立性真的存在。同一个模型的多个实例通常不满足。
- 依赖人类特有机制的：先确认这项能力在构造出的 Cognizer 上功能等价。

## 群体主体性

一个集体算不算真正的主体，要看它的聚合规则能否得出任何成员单独得不出的判断（List & Pettit，群体能动性与 discursive dilemma）。不存在同时满足若干合理条件的完美聚合程序；每加一层投票，就多一层这种问题。任务能分解为子前提时，前提基础的程序优于结论基础的程序。成员间相互负有义务（Gilbert，联合承诺）；主体的边界由决策的规范性闭合划定（Rovane）。

推断：集体的判断质量取决于执行聚合的成员所用的程序，所以 Library 把聚合写成一个成员。

## 治理三难

集中、监督、容错不能同时最大化：

- 集中：协调快、方向统一、能紧急停止；代价是单点故障、反馈失真、错误全局放大。
- 监督：只有独立于被监督者（不由它任命、不由它供给、不由它裁决）才有效，否则退化为自检。监督者持有的是修正权，不是惩罚权。
- 容错：错误局部化、可逆、不全局放大。靠冗余、异质、可回滚、熔断。

可行的做法是分层错开：规则刚性，协调集中方向，执行分散并最小授权，监督独立，容错可逆。平时分权探索，危机集中协调。

## 独立性与集体智能的上限

- **错误相关**：有效独立数 N_eff = N / [1+(N−1)ρ]，降低 ρ 比增加 N 更根本。Condorcet 一类结论假设成员错误大体独立；相关时，群体错误收敛到正的下限，ρ≈0.24 时保留单个主体错误的 21%–90%。不同 provider 不等于错误独立。
- **析取与合取**：任一成员对即可的任务，冗余有效；都对才行的任务，冗余无效。
- **验证吞吐**：报告称存在验证负载阈值 u*≈1.84，超过后逃逸的错误在级联中变为超临界。
- **并行宽度**：约 85% 的程序任务级并行度 ≤5；增加主体超过依赖图的并行宽度后，收益迅速递减。
- **容错上限**：关键决策要容忍 f 个故障主体，需要 N ≥ 3f+1。
- **自组织的 LLM 团队**（arXiv:2602.01011，适用的实验范围待核验）：团队未匹敌最佳成员，性能损失 6.3%–41.1%，瓶颈在专家利用；倾向把专家与非专家的意见「整合性妥协」，随规模增大加剧。推断：对照 Library 预置的规则「聚合是一个成员，用加权，不用简单多数」。
- **投入与收益**（出处待补）：合理使用多个智能体时，投入的 token 倍率换不来同样倍率的能力，但仍然值得；按软件工程的角色分工时，花在协调上的 token 多于花在工作上的。

## 委派的形状

用户的判断，没验证：

- 空上下文的子代理：值得派，当设计派遣、派遣、验收、修订与并入的成本远小于自己做。适合子任务独立、不需要父的工作集；工具输出冗长，隔离能防 context rot（上下文腐化）；验收的一方能独立判断，或子代理的失败是弱验证、父一侧补验证。
- 分支的子代理：继承父的上下文，用前缀的 KV cache 压低重建的钱与派遣的成本。适合子任务要继承父的决策、约束与读过的文件，缓存收益大，结果能追加在尾部并入，不改写主线的中段。扇出能力大于空上下文的子代理。

研究观察，出处待核验：适合派遣的形状是边界清楚、低耦合、不阻塞下一步，不是「复杂就拆」。四种：扇出与归约，能写成 `map(f, xs)`、各 `f(x)` 不共享可变状态，Anthropic 的报告里广度优先的查询是多 agent 优势最明显的场景；高内聚的切分，Co-Coder 按静态分析的依赖图隔离枢纽文件、做社区划分，一次好的分解是依赖图的一次切割，加上写所有权与决策所有权；上下文负担重而结论可压缩，判据是它留在主线会注入大量结束后不需要的中间数据；深链，Attention Tax, Handoff Tax 报告省下的注意力成本超过交接税时分解才占优，账本任务上交叉点在深度 10 左右，且每一环只靠一份压缩的交接物就能开始。不该派的：关键路径上阻塞下一步的、与还在变的本地上下文高度耦合的、两步以内做得完的、说不清要返回什么的。

我们的推断：
- 前两种形状在派遣时就判定得了，后两种的边界随上下文能力、交接物的压缩质量与缓存命中率移动。几种都是 Principal 的策略，机制已在：空上下文的子代理就是交办，交接物是 Signature 的 in；分支的子代理是 Organization 待定里的分身；扇出是几次实例化共用一个 Notify 的 `to`，Race 场景走查过。所以不进 Kernel；Library 以后可以给扇出一个辅助函数，有场景再做。
- 「说不清要返回什么」被结构消解了：每份 Definition 都有 Signature，委托之前就得写出 out。写所有权也是现成的：工作区只有一个主人，改动以 Tree 交回，由 Principal 并入。
- 分支的子代理要省钱，工具列表要与父相同（据记忆，provider 把工具放在前缀的前面，待核验）。这不与授权只收窄冲突：工具说明不是权利，没给它的工具换成同名、同签名、一调用就失败的函数，推出的说明不变，前缀也不断。

## LLM 组合特有的失效

由组合结构本身产生，不是单个组件失败的叠加：

- **角色坍缩**：执行与检验共享表征时，检验超不出执行已经产生的范围。
- **验证剧场**：检验者只看输出，不能访问真实状态时，检查的是外观。一篇预注册实验报告，按输出的评估检测不到编排造成的内部扭曲；它对模型内部状态的前提待核验。
- **级联失效**：语义误差逐级复合，超过某个深度不可恢复；压缩删掉的恰是纠正所需的可追溯性。报告称多 agent 故障率 40–60%。
- **继承漂移**：接收较弱主体的原始轨迹，会继承它的目标漂移。
- **人的监督被捕获**：人加 AI 低于较强的一方（g≈−0.23）；验证负荷越高，自动化偏见越强；展示解释与置信度没有显著改善。
- **幻影护栏**：自我改进的 harness 发明不存在的失败，启用不存在的规则；只看自评指标发现不了。

推断：这些支持 Library 的职责分离与熔断规则、Handoff 只给整理过的结果，以及 Instance 的"改 Agent 的工作方式由 Principal 来做"。

## 出错之后

- **归因**：多智能体错误的因果归因按贡献分配责任、区分根因与传播症状、定位决定性步骤（ProofGraph、CHIEF、A2P）。精度与成本要权衡，可以先粗后细。
- **义务**：承诺是有向的条件关系，状态为空、条件、活跃、满足、违反；违反触发状态转移，不触发惩罚（commitment protocols）。
- **信任调整**：按历史正确率调整一个主体的输出权重、验证强度与路由。这是资源分配，不是惩罚。
