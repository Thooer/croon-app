# 先例

全部待核验：名称、链接、行为来自网页端 LLM 的搜索报告或记忆，只作 App 侧组合与应用设计的线索。

## Library 与 Agent framework

| 先例 | 观察 | 与 App 的关系 |
|---|---|---|
| LangGraph | 共享 state、reducer、checkpointer、interrupt、Send 扇出、supervisor 与 swarm | 对照：共享 state 归一个成员；分支和监督由现有组合表达 |
| OpenAI Agents SDK | handoff、agent-as-tool、guardrail | 回话途径与委托是两种关系；guardrail 是 Middleware |
| AutoGen Selector、MagenticOne | 模型选择发言者，编排者维护任务与进度账本 | 群聊房间与聚合成员 |
| MetaGPT 消息池 | 共享消息池，按兴趣订阅 | 订阅需持有池子的 Port，不用环境权利 |
| Claude Code 动态工作流 | Agent、pipeline、parallel、budget；前缀复用和可恢复脚本 | 动态编排属于 Cognition；Library 封装现有 Instance 与 Language |
| Harness² | 文件化组件、可审查 diff、同输入试跑、独立评估 | Principal 改 Agent 的工作方式；试跑与 Handoff |
| AgentSquare、EvolveR、Memento-Skills | 搜索模块化 Agent 结构，从历史提炼可复用策略 | Library 的认知模式与改进循环候选 |

## 组织与委派

人类组织中可迁移的结构包括：章程先写结构、随后注入人选；审计者独立于被审计者；值班地址由转交系统保持连续；机构只能局部更新，旧工作完成后再交接。

推断：这些落到 App 的 Charter 预置、独立检验、转交者、派单者和 Handoff。动机、惩罚和同质成员的独立错误率不能直接迁移。

## 多 Agent 失效

研究线索：执行与检验共享表征会导致角色坍缩；只看输出会形成验证剧场；逐级委派会积累语义误差；模型实例的错误相关性使简单多数失效；监督负荷会产生自动化偏见。

推断：Library 应分开执行与检验的权利和信息，使用异质方法，不以同质多数替代独立验证；验证吞吐不能超过检验能力；Handoff 交付整理后的结果，不把原始轨迹无条件带入。

## 系统边界与协议

| 先例 | 观察 | 与 App 的关系 |
|---|---|---|
| A2A | AgentCard 描述能力；Task 有可恢复的等待输入状态；每一跳重新认证 | 外部 Agent 是只有 Interface 的服务；中断表现为回话途径 |
| MCP | tools、resources、prompts、sampling、elicitation、roots | 各能力可绑定成 Port；具体绑定是 Plugin 或 App 的提供者 |
| ACP、ANP | 编辑器与 Agent、互不信任 Agent 之间的通信协议 | 系统边界上的候选适配 |

## 组合

研究观察：数据化的 IR、可替换的 Language、经接线发生的效果、持久执行和能力边界分别已有先例，但没有发现把它们组合成同一套制度机的现成实现。

推断：App 不应把这些先例重新做成 Kernel 机制；优先用 Kernel、Language 和宿主 Port 的组合表达。
