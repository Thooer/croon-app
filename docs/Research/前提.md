# 前提的证据

这里是支持应用侧做法的研究线索。全部待核验：名称与数据来自网页端 LLM 的搜索报告，尚未对照原文，只作线索，不作结论的依据。Kernel 的前提证据在 croon 的 docs/Research/前提.md，Lang0 的在 croon-lang0 的 docs/Research/前提.md。

## 截断与续写

研究观察：

- **模型不标记截断。** GLM-j 的 2000 条响应中 63.3% 的思维链在 token 上限处被截断，解析器仍提取成功。OpenThoughts3 有 62% 的样本缺少闭合的 `</think>`。
- **接口层不报告截断。** 一个生产 PR 记录：`finish_reason: "length"` 被翻译成 completed，与真正完成不可区分。
- **自我报告替代不了。** 模型对自己行为比率的直接预测与实际行动相关 r≈0.04；被注入推理的模型多数拒绝披露这种影响。
- **缺少锚点时，恢复建立在虚构的状态上。** 一个运行时从对话转录恢复，转录里有"看似合理的工具结果"，实际的派发从未发生，任务被标为完成；记录者的结论是"快照保存了故事，不是状态"。一个三天的任务从 agent 自己的摘要恢复，引用了从未写过的函数和已被否决的决定。递归摘要几轮后，具体的触发条件丢失。
- **中断有代价。** ContinuityBench：中断使平均成功率从 41.7% 下降到 28.0%。多轮对话比单轮平均下降 39%。agent 的任务成功率几何衰减，16 步内近零。
- **对策都在框架层。** Gemini 的 continuation token 有恢复上限，无进展即停；续写的提示要区分截断的类别，告知错了模型会在错误的前提上继续。

我们的推断：续写的质量由框架注入的信号、状态锚点与前因是否正确决定，不由模型或提示决定。这支持 Library 的"ReAct 遇截断以失败结束、不续写"，Instance 的"只在 Atom 之间打断""恢复靠 Journal 重放"。

## 反馈与修正

研究观察，出处待补，全部待核验：

- **就地编辑优于追加反馈。** 直接改模型上一轮的回复、从改过的上下文接着生成，在五个推理基准上都优于多轮追加反馈，token 少约 79%；只删掉错误片段、不给正确答案，也优于追加。追加反馈的后期，接受率与纠错率持续下降。改写助手的历史本身有正向效应，不能只用上下文变短解释。
- **失败的调用留在上下文里会被模仿。** 放进一次失败的工具调用与错误信息后，模型再发同一调用的概率从 0.06 升到 0.54；起作用的是它的表面形式，「标为失败」的语义贡献很小。
- **多轮改进会覆盖好结果。** 编程任务 12 轮内正确率从 40.7% 跌到 2.5%，最好的一轮比最后一轮高 42.5 个百分点；多轮修订报告，16%–28% 已覆盖的内容与引用出现回归，提示工程与专门的修订子 Agent 都不易修复。
- **方向引导看位置。** 只指方向、不给答案，平均提升 9.4%；放在推理链的末端最好，开头次之，中间最差；聚焦一个维度会改变整体的注意力分布，效应量可超过 50%。
- **LLM 当裁判会低估反馈。** 它偏好没有反馈的基线输出，模型靠反馈修好了也常认不出；人类反馈纠正结果的比例，即使对 o1 级的模型也不到 50%。
- **相对比较比绝对打分可靠。** LLM 识别设计优缺点的模式与人高度一致（余弦相似度大于 0.96），绝对评分有系统性差异（Cohen's d 为 0.9–1.1）。

我们的推断：这些支持 README 前提表里「早先的值压制后来的」「否定的指令不如肯定的可靠」「没有自己的停止与检验」三行，方向引导与「关键信息埋得越深越容易被忽略」可能同向。由此来的做法都是策略：失败怎样呈现、保留哪一版、聚合按相对还是绝对，由写认知模式与 Charter 的一方选；机制已留出空间：ReAct 自己构造消息历史，Middleware 能在 engine 之前改写，Journal 只追加、原始记录都在，聚合与检验的规则写在各自的 Definition 里。就地编辑在 Croon 里就是从一段历史开出新 Instance。
