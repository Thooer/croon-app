# 借鉴组织

全部待核验：名称与数据来自网页端 LLM 的搜索报告或记忆，只作 App 侧组织与 Library 的线索。

## 群体主体性

研究线索：集体判断的质量取决于聚合规则；任务能分解为子前提时，先聚合基础前提通常优于直接聚合结论。

推断：聚合由一个成员执行；任务先分解再聚合；规则写进预置 Charter 或成员 Definition。

## 治理三难

研究线索：集中便于协调与紧急停止，但有单点故障；监督只有独立于被监督者才有效；容错需要局部化、可逆和熔断。

推断：App 的组织分层为规则刚性、协调集中、执行分散、监督独立、危机可介入。监督者持有观察与纠正权，不以惩罚为机制。

## 独立性与集体智能

研究线索：错误相关性降低简单多数的收益；不同 provider 不等于错误独立；并行宽度超过依赖图后收益递减；验证负载过高会让错误级联。

推断：预置组织按任务选择冗余、异质模型和加权聚合；生成吞吐不超过检验吞吐；这些是 Application 策略，不是 Kernel 保证。

## 委派的形状

适合委派的候选形状是：边界清楚、低耦合、不阻塞下一步；扇出与归约；高内聚切分；上下文负担重但结论可压缩；或深链中每一环都能以明确交接物继续。不适合委派的是关键路径阻塞、依赖持续变化的本地上下文、两步内可完成、或说不清返回物的任务。

推断：空上下文子 Agent 是普通交办；分支子 Agent 是历史分支候选；扇出是多次实例化与 Notify 的组合；返回形状由 Definition Signature 固定。写所有权由工作区 Bundle 的主人承担。

## LLM 组合特有的失效

角色坍缩、验证剧场、级联失效、继承漂移、人的监督被捕获和幻影护栏，都是组合结构产生的风险。

推断：Library 分开执行与检验的权利和信息；独立检验直接读事实；Handoff 只给整理后的结果；改 Agent 的工作方式由 Principal 做并检验。

## 出错之后

归因应按贡献和决定性步骤定位；承诺是有向的条件关系；历史正确率可以调整资源分配、验证强度和路由，但不是惩罚机制。
