# 包与家目录

Library 是一组包；用户有一个家目录，装着它们，也装着工具清单与技能。管理器是看、装、载、实例化这四个操作。本文写包是什么、家目录属于谁、管理器管什么。

## 包

包是一份目录 Bundle，里面是 Lang0 模块。目录顶层是 import 的起点，装载的语义见 croon-lang0:docs/README.md「模块」。一个包带一份手写的 README.md，说明它是什么、怎样用。

- **主体也是包。** 带入口模块、其中有 `main` 的包就是一个可以实例化的主体。Library 里预置的包与运行中造出来的主体是同一种东西：一个目录，一个入口。名字就是路径，由造它的一方起；运行中造的，名字是模型自己起的，满足 Library/README.md「模型看到的名字极简」。
- **公开面**：名字以下划线开头的不公开，不进索引。
- **索引**：宿主从源码推出，规则与推 Interface、`croon.tool` 的说明相同：签名、类型、docstring 与其中的 `Args:`，Port 与 TypedDict 一并收。索引是源码的派生物，不是第二份事实；它在建包时生成，随包一起固定，所以永远与代码的版本对得上。推导只有宿主做得到，见 ../Host/README.md「构造的推导」。
- **按层展开**：一句话（包与模块的 docstring 首行）、README、模块索引、源码。模型按需要往下读，每一层作为工具结果进入历史；常驻的只有一行说明，所以前缀稳定。
- **例子**是包里可以直接运行的主体。测试负责构造并运行它们，例子因此不会过期；模型可以照抄它的源码，也可以直接实例化它。
- **生成模块**由宿主从 Port 规格生成，与手写的包一起固定进目录 Bundle，重放不随宿主构建改变类型：library.kernel 只提供 KernelPort 的 Port spec 与 Outcome；library.model 的 Generate 来自 model.generate；library.directory 的 Exec 来自 directory.exec；library.infer 的 Infer 来自 definition.infer。它们的源码不进 Git，由本仓库的生成器产生。手写的源码在仓库根的 library/。

## 家目录

家目录是用户的内容：Library 里的包、工具清单、技能。它是一个工作区，规则见 Runtime.md「工作区」。

- **属于用户，不属于手。** 装上的包与载入的清单要在手结束之后还在，也要让用户的别的手看得见，所以不放在某一个手里。手经接线拿到读与提交的权利，见 Presets.md「预置给谁」。第一版把它作为目录 Bundle 交给手，像用户仓库一样；这次运行里装的东西在这次运行里有效，结束时不写回。留存与共享见待定。
- **与仓库分开**：它与用户仓库是两个工作区，当前位置各自移动；物化结果时不带家目录。

## 管理器

管理器是 Library 里的函数，不是 Definition，也没有自己的身份。它有四个操作：

| 操作 | 做什么 |
|---|---|
| 看 | 本地有什么、怎么用：按「包」里的层展开返回 |
| 装 | 把一个包放进家目录：派生新的目录 Bundle，再采用；能 diff，能回滚 |
| 载 | 把包里的主体或函数接好线，写进工具清单；见 Runtime.md「工具」 |
| 实例化 | 直接运行一个包、一个路径或一份源码；见 Runtime.md「交办」 |

人经客户端做的与手经工具做的是同一组操作，落在同一份实现上。W0 自带的只有管理器，别的能力都先装、再载。

## 待定

- 联网下载包：依赖 croon:docs/Kernel/README.md「待定」里的「系统边界」，第一版不做。内容寻址的哈希就是锁定。第三方的包没有环境权利，只能用接给它的 Reference，所以风险只有两处：接给它什么，以及它的输出对模型的影响；后者在作者与使用者不再是同一个人时才出现。没有场景。
- 多库组合：不同的包同时载入时，要不要识别组合、给结合使用的教程；识别到什么程度。没有场景。
- 家目录的留存与共享：跨运行留存、几个手共用，由保管者持有当前位置，写法与 Runtime.md 待定「共享工作区的写法」相同。没有场景。
- 模型能不能发布模块：发布主体（造出来放进家目录）第一版就要；发布模块（辅助函数供它之后造的几个主体共用）也会影响别的主体的代码，发布权要由接线决定，等有保管者再放开。没有场景。
- 索引的推导需要 croon-lang0 的一个公开 API：枚举一个模块的顶层公开定义并逐个推导，含 Port 与 TypedDict。这是上游的缺口，要在 croon-lang0 补上并写进它的头部。
- 每一层展开给多少内容：由实验定，见 ../Plan.md「下一步」。

参考：Runtime.md（工具、交办、工作区）；Presets.md（预置给谁）；../Host/README.md（构造的推导）。
